# POST — Learning

Unlike `GET`, which places parameters in the URL, `POST` sends data inside the HTTP request body.

This provides several advantages:

- **Lack of Logging:** Large amounts of data, such as uploaded files, do not have to appear directly in the URL.
- **Less Encoding Requirements:** The request body can contain binary data and requires less URL-specific encoding.
- **More Data:** `POST` is not constrained by typical URL length limitations.

`POST` is commonly used for:

- Login forms
- Sending form data
- File uploads
- API requests
- JSON data

---

## Login Forms

Traditional web application login forms commonly send credentials using a `POST` request.

Example request body:

```text
username=admin&password=admin
```

A similar request can be reproduced manually with cURL:

```bash
curl -X POST -d 'username=admin&password=admin' http://<SERVER_IP>:<PORT>/
```

Useful cURL options:

| Option | Description |
| --- | --- |
| `-X POST` | Explicitly sends a `POST` request. |
| `-d` | Adds data to the request body. |
| `-L` | Follows HTTP redirects. |
| `-i` | Displays response headers. |
| `-v` | Displays verbose request and response information. |

> **Tip:** Login forms often redirect the user after successful authentication. The `-L` option can be used to follow these redirects.

## Authenticated Cookies

After successful authentication, the server may return a session cookie using the `Set-Cookie` response header.

Example:

```http
Set-Cookie: PHPSESSID=c1nsa6op7vtk7kdis7bcnbadf1; path=/
```

The browser stores this cookie and automatically sends it with future requests, allowing the authenticated session to persist.

A cookie can be supplied to cURL using `-b`:

```bash
curl -b 'PHPSESSID=c1nsa6op7vtk7kdis7bcnbadf1' http://<SERVER_IP>:<PORT>/
```

It can also be supplied manually through the `Cookie` header:

```bash
curl -H 'Cookie: PHPSESSID=c1nsa6op7vtk7kdis7bcnbadf1' http://<SERVER_IP>:<PORT>/
```

General request header format:

```http
Cookie: PHPSESSID=<SESSION_ID>
```

A valid authenticated session cookie may therefore be sufficient to access authenticated parts of a web application without resending the username and password.

Browser DevTools can be used to inspect and modify cookies through the **Storage** tab.

## JSON Data

`POST` requests are also commonly used by APIs to transmit JSON data.

Example request body:

```json
{"search":"london"}
```

When sending JSON, the request usually specifies:

```http
Content-Type: application/json
```

Example HTTP request:

```http
POST /search.php HTTP/1.1
Host: <SERVER_IP>
Content-Type: application/json
Cookie: PHPSESSID=<SESSION_ID>

{"search":"london"}
```

The same request can be reproduced with cURL:

```bash
curl -X POST 
-d '{"search":"london"}' 
-b 'PHPSESSID=c1nsa6op7vtk7kdis7bcnbadf1' 
-H 'Content-Type: application/json' 
http://<SERVER_IP>:<PORT>/search.php
```

Example response:

```json
["London (UK)"]
```

This allows interaction with backend endpoints directly, without using the application's frontend.

## Browser DevTools

The **Network** tab can be used to inspect `POST` requests generated by the application.

Useful options include:

```text
Copy > Copy as cURL
```

to reproduce the request from a terminal, and:

```text
Copy > Copy as Fetch
```

to reproduce the request using JavaScript from the browser console.

When analyzing a `POST` request, important elements include:

- Request URL
- HTTP method
- Request body
- `Content-Type`
- Authentication cookies
- Other required headers
- Server response

Reproducing requests directly with cURL or Fetch is useful during web application assessments and bug bounty testing because it allows direct interaction with backend endpoints.
