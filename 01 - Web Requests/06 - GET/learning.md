# GET — Learning

The `GET` method is the default HTTP method used by browsers when visiting a URL. It is mainly used to retrieve resources from a server.

Browser DevTools, especially the **Network** tab, can be used to inspect requests and understand how a web application communicates with its backend.

---

## HTTP Basic Auth

HTTP Basic Authentication is handled directly by the webserver to protect a page or directory.

Unlike traditional login forms, credentials are not sent through a `POST` form. Instead, they are sent using the HTTP `Authorization` header.

Without valid credentials, the server typically responds with:

```http
HTTP/1.1 401 Authorization Required
WWW-Authenticate: Basic realm="Access denied"
```

The `401 Authorization Required` status and `WWW-Authenticate` header indicate that authentication is required.

Credentials can be provided with cURL using `-u`:

```bash
curl -u admin:admin http://<SERVER_IP>:<PORT>/
```

They can also be included directly in the URL:

```bash
curl http://admin:admin@<SERVER_IP>:<PORT>/
```

General format:

```text
http://username:password@host/
```

---

## HTTP Authorization Header

With Basic Authentication, credentials are sent through the `Authorization` header.

Example:

```http
Authorization: Basic YWRtaW46YWRtaW4=
```

The value `YWRtaW46YWRtaW4=` is the Base64 representation of:

```text
admin:admin
```

The header can be manually supplied with cURL using `-H`:

```bash
curl -H 'Authorization: Basic YWRtaW46YWRtaW4=' http://<SERVER_IP>:<PORT>/
```

General format:

```http
Authorization: Basic <base64(username:password)>
```

Modern authentication systems may instead use a `Bearer` token:

```http
Authorization: Bearer <token>
```

For example, JWT authentication commonly uses the `Bearer` scheme.

> **Note:** Base64 is an encoding format, not encryption.

## GET Parameters

Parameters of a `GET` request are included directly in the URL as part of the query string.

Example:

```text
/search.php?search=le
```

This contains:

| Element | Value |
| --- | --- |
| Path | `/search.php` |
| Parameter | `search` |
| Value | `le` |

General format:

```text
/path?parameter=value
```

Multiple parameters are separated using `&`:

```text
/path?parameter1=value1&parameter2=value2
```

A `GET` request can be reproduced directly with cURL:

```bash
curl 'http://<SERVER_IP>:<PORT>/search.php?search=le' -H 'Authorization: Basic YWRtaW46YWRtaW4='
```

Example response:

```text
Leeds (UK)
Leicester (UK)
```

## Browser DevTools

The **Network** tab can be used to analyze requests generated by a web application.

Typical workflow:

1. Open browser DevTools.
2. Go to the **Network** tab.
3. Clear previous requests.
4. Perform an action in the application.
5. Identify the generated request.
6. Inspect its method, URL, parameters, headers, and response.

Requests can be reproduced using:

```text
Copy > Copy as cURL
```

This generates a cURL command containing the request URL and headers.

Most automatically copied headers can usually be removed, keeping only those required by the application, such as:

```http
Authorization: Basic ...
```

A request can also be copied as JavaScript:

```text
Copy > Copy as Fetch
```

and executed directly from the browser's JavaScript console.

This technique is particularly useful during web application assessments and bug bounty testing to understand how the frontend communicates with backend endpoints.
